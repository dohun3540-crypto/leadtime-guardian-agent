# 핵심 사례 스토리 초안

모든 사례는 검증 대기. 현재는 정적 설명안이며 Live 성공을 주장하지 않는다.

- C001: 세 문서가 같은 발주에 속하는지 먼저 확인한다. 동일 운영 Job의 정규화 결과를 Python 입력과 연결하고, 부족량 변화와 견적을 설명한다. 0→60 및 60,500 KRW는 요구 조건으로만 표시한다.
- C013: PO1/PO999 불일치를 추정으로 고치지 않는다. 같은 사례의 실제 차단 결과와 QA 근거가 확보되면 안전 차단 장면으로 사용한다.
- C008: R1/R2를 구분하고 R2만 ETA가 바뀌는지 확인한다. 입고량을 중복 소비하지 않는 결과가 확보된 후 설명한다.
- C017: 한국어 원문 날짜를 먼저 보여주고 근거가 있는 ISO 값과 나란히 대조한다. 없는 날짜를 추정하지 않는다.

각 장면의 수치는 DEMO_EVIDENCE_TABLE.csv의 미검증 상태를 해소하기 전 성과로 읽지 않는다. QA가 별도 Job이면 Normalize 원본 SHA와 QA 입력의 연결 증거를 유지한다.
